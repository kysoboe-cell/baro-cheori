## 1. 발견된 진짜 문제 — v3 디자인 시스템이 절반만 적용돼 있습니다

v3(가독성 개편)는 홈·상세 페이지에만 적용됐고, **나머지 페이지는 옛 디자인 그대로**입니다. 실측:

| 페이지 | h1 | h2 | 본문 | 16px 미만 요소 |
|---|---|---|---|---|
| **상세 (v3 적용됨 · 기준)** | **30px** | — | **17px** | **0개** |
| 업체 `/company/[slug]` — **23페이지** | **48px** | — | 14~15px | **33개** |
| `/privacy` | 36px | 20px | 14px | 3개 |
| `/about` | 36px | 20px | 14px | 1개 |
| `/information-policy` | 36px | 18px | 14px | 2개 |

v3 토큰 기준값은 **display 28/40 · h1 24/30 · h2 20/22 · h3 17/18 · 본문 17px**입니다. 48px과 36px은 토큰에 아예 없는 크기입니다.

### 왜 이게 중요한가

1. **업체 페이지는 23개나 되고, 헤더 "업체 찾기"의 도착지입니다.** 홈 → 업체 → 상세로 가는 길에서 **가운데 한 칸만 옛 디자인**입니다. 사용자가 세 가지 디자인을 연달아 보게 됩니다.
2. **업체 페이지 안에서도 카드 스타일이 두 종류가 섞여 있습니다.** 실측으로 확인된 두 클래스:
   - 신형: `rounded-xl border border-line bg-white p-3`
   - 구형: `rounded-2xl border border-gray-200 bg-white p-6 shadow-sm transition hover:-translate-y-0.5 hover:border-gray-400 hover:shadow-md`
   v4에서 모바일 압축 그리드를 넣을 때 상위 6개만 새 카드로 바꾸고 **나머지는 옛 카드가 남았습니다.** 쿠팡 페이지는 카드 14개에 두 스타일이 공존합니다. 한 화면에 그림자 있는 카드와 없는 카드가 같이 보입니다.
3. **`/privacy`와 `/about`은 애드센스 심사원이 반드시 여는 페이지입니다.** 신청 직전에 정리해 두는 게 좋습니다.

## 2. 클코 작업 A — v3 토큰 전면 통일

### 2-1. 매핑 규칙 (아래 파일 전부에 동일 적용)

| 옛 클래스 | 바꿀 값 |
|---|---|
| `text-4xl` / `sm:text-5xl` / `text-3xl` (h1) | `text-h1 md:text-h1-md` |
| `text-2xl` / `text-xl` (h2) | `text-h2 md:text-h2-md` |
| `text-lg` (h3·카드 제목) | `text-h3 md:text-h3-md` |
| `text-base` / 본문 `text-sm` | `text-body md:text-body-md` |
| 보조 설명 `text-sm` | `text-body-sm` |
| 라벨·날짜 `text-xs` | `text-caption` |
| `text-gray-950` / `text-slate-900` / `text-slate-950` | `text-ink-900` |
| `text-gray-700` | `text-ink-700` |
| `text-gray-600` / `text-slate-600` | `text-ink-600`  ※ 이보다 옅은 회색은 텍스트에 쓰지 말 것 |
| `text-gray-500` 이하 (텍스트) | `text-ink-600` (아이콘·플레이스홀더만 `text-ink-500`) |
| `border-gray-200` / `border-slate-200` | `border-line` |
| `bg-gray-50` / `bg-slate-50` | `bg-bg-soft` |
| `text-primary-700` | `text-primary` |
| `rounded-2xl` | `rounded-xl` |

**`font-bold`(700)은 그대로 둡니다.** v3가 금지한 건 900이지 700이 아닙니다. 단 `font-extrabold`·`font-black`이 있으면 `font-bold`로 낮추세요.

### 2-2. `app/company/[slug]/page.tsx` — 가장 중요

1. 위 매핑 전면 적용 (`main`의 `bg-gray-50` 포함)
2. h1을 `text-4xl font-bold tracking-tight sm:text-5xl` → **`text-h1 md:text-h1-md text-ink-900`**
3. **카드 스타일을 한 종류로 통일합니다.** 구형 카드(`rounded-2xl … shadow-sm hover:-translate-y-0.5 hover:shadow-md`)를 전부 없애고, 상위 6개에 쓰는 신형 카드 스타일로 맞추세요. `hover:-translate-y-0.5`·`hover:shadow-md` 같은 들썩임은 v3의 "박스 대신 여백" 방향과 반대라 되살리지 마세요.
   - 목록 렌더 분기가 둘로 나뉘어 있다면 **카드 컴포넌트를 하나로 뽑아서 양쪽이 같은 걸 쓰게** 하세요. 그래야 다음에 또 갈라지지 않습니다.
4. 카드 제목은 `text-h3`, 설명은 `text-body-sm text-ink-600`
5. 카드 전체가 탭 영역이므로 `min-h-` 로 48px 이상 보장

### 2-3. `/privacy` · `/about` · `/information-policy` · `not-found.tsx`

위 매핑 적용. 이 네 페이지는 글 중심이라 **읽기 폭 680px**(`max-w-[680px]`)도 같이 적용하세요. 지금은 폭이 넓어 한 줄이 너무 깁니다.

### 2-4. `app/components/SiteFooter.tsx`

푸터가 다크(`bg-gray-950`)인 건 그대로 둡니다 — 의도된 디자인입니다. 다만 **토큰과 옛 클래스가 섞여 있습니다**(`text-body-sm` + `text-gray-300`이 한 줄에). 다크 배경용 색을 정해서 일관되게 쓰세요:
- 본문 `text-gray-300` → 유지하되 전 요소 통일
- `border-gray-200`(밝은 선이 다크 배경에 얹혀 있음 — 어색합니다) → `border-gray-800`로 통일
- 글자 크기는 전부 `text-body-sm` / `text-caption` 토큰으로

### 2-5. `app/search/page.tsx` 잔여 1건

72행 `text-lg` (아이콘용) → `text-h3` 또는 아이콘이면 그대로 둬도 됩니다. 확인만 하세요.

## 3. 클코 작업 B — 쿠팡 와우 썸네일 7장 반영

이월돼 있던 잔손질을 제가 처리했습니다. `콘텐츠-초안\쿠팡와우_썸네일_7장.zip`

- 480×600 (4:5) WebP 7장, 장당 8~40KB
- **자동 크롭이 아니라 원본을 한 장씩 눈으로 보고 크롭 위치를 정했습니다.** 코랄 자동 감지는 쿠팡 앱 자체 색과 겹쳐 실패했습니다.
- 크롭 기준: 각 장에서 **실제로 눌러야 하는 대상**이 썸네일 안에 보이도록
  - step1 → 하단 마이쿠팡 아이콘, step2 → 우상단 톱니바퀴, step3 → 하단 와우 멤버십 행
  - step4 → 멤버십 상단, **step5 → 월회비 결제수단 아래 [해지하기] 박스**
  - step6 → 붙잡는 화면, **step7 → 파란 [유지하기] + 흰색 [해지 신청 완료하기] 둘 다**
  - 지금 쓰는 `object-top` 폴백이면 step1·3·5·7은 **정작 눌러야 할 대상이 안 잘려 들어옵니다.** 이 4장이 실제 개선분입니다.

작업:
1. zip을 프로젝트 루트에서 풀면 `public/images/guides/coupang-wow-cancel/`에 `step1-home-thumb.webp` ~ `step7-final-thumb.webp`가 들어갑니다
2. `app/data/companies/coupang.ts`의 `wow-membership-cancel` → `screenshotGuide.steps` 7개에 `thumb` 필드를 추가합니다 (`img` 파일명에 `-thumb`만 붙인 경로):

```ts
{ n: 1, img: "/images/guides/coupang-wow-cancel/step1-home.webp",
  thumb: "/images/guides/coupang-wow-cancel/step1-home-thumb.webp", ... },
{ n: 2, ... thumb: "/images/guides/coupang-wow-cancel/step2-mypage-thumb.webp", ... },
{ n: 3, ... thumb: "/images/guides/coupang-wow-cancel/step3-myinfo-thumb.webp", ... },
{ n: 4, ... thumb: "/images/guides/coupang-wow-cancel/step4-wow-top-thumb.webp", ... },
{ n: 5, ... thumb: "/images/guides/coupang-wow-cancel/step5-cancel-row-thumb.webp", ... },
{ n: 6, ... thumb: "/images/guides/coupang-wow-cancel/step6-retention-thumb.webp", ... },
{ n: 7, ... thumb: "/images/guides/coupang-wow-cancel/step7-final-thumb.webp", ... },
```

`caption`·`alt`·`warning`·`linkedStep`·`howToImage`는 **건드리지 마세요.**

3. `ScreenshotGuide.tsx`가 `item.thumb ?? item.img`를 쓰고 `thumb`가 있으면 `object-top`을 빼도록 이미 돼 있으므로 컴포넌트 수정은 필요 없습니다.

## 4. 클코 작업 C — 허브 breadcrumb 구조화 데이터 손보기

`app/problem/[problemSlug]/page.tsx`의 BreadcrumbList에서 **position 1(홈)과 position 2(상황별)가 같은 URL**(`absoluteUrl("/")`)을 가리킵니다. 같은 URL이 두 단계로 들어가면 구글이 이상하게 볼 수 있습니다.

가장 간단한 수정: **position 2를 없애고 홈 → 문제 두 단계로** 만드세요.

```ts
itemListElement: [
  { "@type": "ListItem", position: 1, name: "홈", item: absoluteUrl("/") },
  { "@type": "ListItem", position: 2, name: problem.title, item: absoluteUrl(path) },
],
```

화면에 보이는 브레드크럼 텍스트("홈 / 상황별 / …")는 그대로 둬도 됩니다.

## 6. 클로드 코드 명령문 (그대로 복사해서 붙여넣기)

```

배경: v6는 검증 통과했다. 그런데 실사이트를 computed style로 측정해 보니 v3 디자인 토큰이 절반만 적용돼 있었다. 업체 페이지(/company/[slug], 23개)는 h1이 48px에 16px 미만 글자가 33개고, 한 페이지 안에 카드 스타일이 두 종류 섞여 있다. /privacy, /about, /information-policy도 옛 클래스 그대로다. 애드센스 심사원이 privacy와 about을 반드시 보기 때문에 신청 전에 정리한다.

작업 순서:

6. npm run build → npm run deploy → 실사이트 재확인 → 커밋 → push → CLAUDE.md "0. 최신 상태 요약" 갱신.

주의:
- 이건 디자인 통일 작업이다. 문구나 구조를 바꾸지 마라. 색·크기·굵기·간격만 손댄다.

- 새 컴포넌트를 만들 때도 v3 토큰(최소 14px, 탭 48px, 코랄 화면당 1회)을 지켜라.
```
