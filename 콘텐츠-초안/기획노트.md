## 4. 확정된 원칙 (바꾸려면 명시적 합의 필요)

**콘텐츠·카피**
- **거짓 0% 카피** — 실제로 제공하지 않는 걸 문구로 약속하지 않는다
- 메인 헤드라인: "복잡한 ARS 싫으셨죠?" / 서브: "처리 순서와 진짜 필요한 연락처까지, 검색 한 번이면 바로 나와요. 완전 무료입니다."
- 카드·메뉴 순서는 **인기도(실제 검색 수요) 기준**. 근거는 `콘텐츠_보강_우선순위.md`(구글 트렌드)

**링크 (v5 신설)**
- **문구에 업체명이 없으면 특정 업체 페이지로 직결 금지.** 반드시 `/problem/...` 상황 허브를 거쳐 사용자가 업체를 고르게 한다. 홈 `page.tsx`에 빌드를 깨뜨리는 가드레일이 들어감

**디자인 (스펙 v3)**
- 색: Primary #0f766e(틸), Accent #e85d3f(코랄, 화면당 1회), 배경 #f0fdfa
- 본문 17px/1.65(데스크톱 18), 굵기는 700/600 두 단계만 (**900 금지**), 최소 글자 14px
- 회색 5단계 #191f28 / #333d4b / #4e5968 / #6b7684(텍스트 하한) / #8b95a1(아이콘만), 선 #e5e8eb
- 탭 영역 48px, 읽기 폭 680px, 박스 대신 여백. 기준 뷰포트 390px(**모바일 우선**)
- 폰트 Pretendard dynamic subset CDN (무료, SIL OFL)

**스샷 가이드**
- **Top 10 페이지 한정.** 버튼이 숨겨졌거나 함정이 있는 페이지만. 조회·안내성 페이지는 텍스트가 정답
- 페이지당 3~5장, 같은 회사끼리 재사용. 판매자별 화면이 다른 곳(스마트스토어)은 부적합
- 레이아웃: 모바일 3열 격자(썸네일 4:5) + `<dialog>` 라이트박스. 단계 리스트 직후 1회만
- **포기 기준**: 8장 초과하거나 썸네일에서 버튼이 안 보이면 그 페이지는 텍스트만
- **처리순서 번호 = 스샷 번호** (v5 신설). 스샷 n장이면 텍스트 단계도 같은 순서·같은 번호, `linkedStep: n`은 1:1
- 개인정보 가림 필수(이름·주소·연락처·이메일·계좌·금액·결제일 등) + 상태바 크롭 + 신선도 날짜 표시
- 썸네일 크롭은 **눌러야 할 대상이 보이게** 한 장씩 눈으로 정한다(코랄 자동 감지는 앱 자체 색과 겹쳐 실패). 원본에 박힌 번호 배지가 크롭에 들어오면 격자 오버레이 번호와 겹치니 잘라낼 것

**후원 (v8 신설)**
- 후원 경로는 **본문을 가리지 않는 자리에만**: 푸터 블록(전 기기 공통) + "도움됐어요" 클릭 직후 한 줄 + 데스크톱 헤더 pill
- "아쉬워요"를 누른 사람에게는 후원을 권하지 않는다
- 모바일 플로팅 버튼 금지(v3 결정 유지), 하단 고정 CTA 옆 금지

**광고 (v6 신설)**
- 광고는 **섹션 경계에만**. 금지: 콜아웃 내부, 처리순서 리스트 내부, 전화·공식 버튼 인접(오클릭 정책 위반 소지), 홈 첫 화면, 상세 페이지의 anchor 광고(하단 고정 CTA와 충돌)
- 승인 후 1차는 **수동 배치**(in-article), 자동광고는 나중에 실험 기능으로 비교
- 수익 기대치는 정직하게: 생활정보 RPM 후기 기준 1천5백~2만 원/1000PV. 월 1만 PV ≈ 1~4만 원. **트래픽이 본게임**

## 5. 재사용되는 운영·기술 팁

- **구글 서비스는 열면 무조건 연세계정으로 시작** → 작업 전 우측 상단에서 **kysoboe@gmail.com으로 전환**. 인증 실패의 단골 원인
  - 빠른 방법: URL에 **`&authuser=kysoboe@gmail.com`**을 붙이면 바로 전환됨 (서치콘솔에서 실측 성공). 전환되면 주소가 `/u/1/`로 바뀜
- **서치콘솔 URL 검사 순서**: 검색창 클릭 → 2초 기다린 뒤 입력(바로 치면 안 먹음) → Enter → 10초 대기 → REQUEST INDEXING → **뜬 모달을 Dismiss** (안 닫으면 다음 입력이 막힘)
- **⚠ 클라우드 예약 실행(스케줄된 작업)에서는 서치콘솔·GA4 확인이 원천 불가** (2026-08-21 실측). 예약 실행은 유석 님 PC·브라우저·로그인 세션에 전혀 연결되지 않고, **WebFetch조차 승인 프롬프트 때문에 막힌다**(자리에 아무도 없어 승인할 사람이 없음). 로그인·브라우저가 필요한 점검은 **유석 님이 데스크톱 앱을 켜 둔 대화 세션에서만** 돌릴 것. (8/27 예약 점검은 이 이유로 8/21에 삭제함 — 색인 확인은 대화에서 "상태 어때?" 한마디로 처리)
- **서치콘솔 신규 속성은 집계 보고서(Pages·Performance)가 며칠 늦다** — 등록 직후엔 "Processing data"가 정상. 그동안은 URL 검사가 유일하게 믿을 수 있는 확인 수단. WebSearch 도구는 `site:` 연산자를 못 쓰고 미국 로케일이라 무용
- **디바이스에서 스테이징한 파일 사본은 시간이 지나면 낡는다** — 클코가 고친 뒤 코드를 검토할 땐 **반드시 다시 스테이징**할 것. 낡은 사본으로 "버그다"라고 오진한 적 있음 (mtime 비교로 확인)
- **배포 검증은 로컬 파일이 아니라 실사이트로**: WebFetch로 페이지의 실제 링크·href를 바로 확인 가능(사이트맵.xml도 WebFetch로 슬러그 찾기 가능). `<head>`에 스크립트가 실제로 박혔는지처럼 WebFetch가 놓치는 것은 브라우저에서 `document.querySelector`로 직접 확인
- **Claude 확장은 naver.com 접근이 차단** → 네이버 대시보드는 "유석 님 클릭 + Claude 순서 안내" 조합
- **Daum 검색등록은 alert 창 남발**이라 자동화 상성 최악 → 직접 하는 게 빠름
- 서치어드바이저 사이트맵은 **전체 URL**로 입력해야 통과
- **배포는 항상 `npm run deploy`.** Cloudflare Git 자동빌드는 원래 고장 상태라 실패 알림 무시해도 됨
- 클코 playwright 크롬: `npx playwright install chromium` (chrome 아님 — 관리자 권한 불필요)
- `npm run deploy`가 `.open-next` 삭제 권한 오류로 실패하면 → **dev 서버가 떠 있어서 폴더가 잠긴 것.** dev 끄고 폴더 지우면 됨
- **배포 직후 새 URL이 404여도 1~2분 전파 지연이 정상** — 바로 실패로 보지 말고 재확인
- **공개 페이지 모바일 캡처 기법**: 웨일 창은 최대화라 resize가 안 먹음 → 같은 도메인 위에 390px iframe + CSS zoom 1.53으로 띄워 캡처(약 1.9배 해상도). 삼성·LG는 OK, **CJ대한통운은 UA 기반 PC 전용**이라 불가
