## 0. 진단 요약 (읽고 시작할 것)

### 문제 A — 업체명 없는 진입점이 임의의 한 업체로 직결됨

`app/page.tsx`의 `quickStarts` / `situationTasks`가 **문구에는 업체명이 없는데 코드에는 특정 업체가 하드코딩**되어 있다.

| 홈에서 누르는 문구 | 지금 도착하는 곳 | 문제 |
|---|---|---|
| 해지했는데 또 결제됐어요 | `/company/netflix/charged-after-cancel` | 넷플릭스라고 한 적 없음 |
| 카드를 잃어버렸어요 | `/company/kb-card/lost-card` | 어느 카드사인지 물어본 적 없음 |
| 가전 수리비, 부르기 전에 궁금해요 | `/company/samsung-electronics/repair-cost-warranty` | 삼성이라고 한 적 없음 |
| 반품 신청이 막혔을 때 | `/company/coupang/return-refund` | 쿠팡 고정 |
| 택배가 어디 있는지 모를 때 | `/company/cj-logistics/delivery-tracking` | CJ 고정 |
| 인터넷 해지 전에 돈이… | `/company/kt/termination-fee` | KT 고정 |
| 카드를 다시 받아야 할 때 | `/company/samsung-card/card-reissue` | 삼성카드 고정 |
| 휴대폰을 잃어버렸을 때 | `/company/kt/lost-phone` | KT 고정 |
| 가전제품이 갑자기 안 될 때 | `/company/samsung-electronics/self-check` | 삼성 고정 |

→ **해결: "업체를 고르는 중간 화면"(상황 허브)을 만들고, 문구에 업체명이 없는 진입점은 전부 허브로 보낸다.**
덤으로 `카드 분실신고`, `구독 해지했는데 결제됨` 같은 **업체명 없는 검색어를 받을 페이지가 새로 10개 생긴다** — 지금은 그런 검색어에 대응하는 페이지가 사이트에 하나도 없다.

### 문제 B — 스샷 있는 페이지의 처리순서가 스샷과 어긋남

`app/company/[slug]/[serviceSlug]/page.tsx`에서 "화면 보기" 버튼을 이렇게 찾는다:

```ts
const linkedGuideStep = guideSteps.find(
  (guideStep) => guideStep.linkedStep === index + 1
);
```

`find`는 **첫 번째 하나만** 집는다. 그런데 데이터에는 스샷 여러 장이 같은 `linkedStep`을 가리키고 있다. 그래서 **뒤쪽 스샷은 처리순서에서 영영 열리지 않는다.**

실측 결과 3개 페이지 전부 어긋나 있음:

**① 쿠팡 와우 해지 — 텍스트 5단계 vs 스샷 7장 (가장 심각)**

| 처리순서 | 실제로 열리는 스샷 | 판정 |
|---|---|---|
| 1 마이쿠팡 | 1 마이쿠팡 | OK |
| 2 [와우 멤버십]을 누릅니다 | 2 **설정(톱니바퀴)** | 엉뚱함 |
| 3 화면 아래의 [해지하기] | 4 **아래로 스크롤** | 엉뚱함 |
| 4 [내가 받고 있는 혜택 포기하기] | 6 붙잡는 화면 | 버튼명 불일치 |
| 5 해지 완료 확인 | — | 없음 |

- 텍스트 단계에 **설정(톱니바퀴) 단계가 통째로 빠져 있음**
- **"중간까지만 스크롤하세요"** 경고가 처리순서에 없음. 데이터상 `screenshotGuide.steps[4].warning`에만 들어 있고, 그 warning은 **라이트박스 안에서만** 렌더된다 → 스샷 격자를 열고 5번 썸네일을 눌러야 겨우 보임
- 마지막 함정(**파란 [유지하기]가 아니라 흰색 [해지 신청 완료하기]**)도 처리순서에 없음. 이 페이지의 최대 차별점인데 텍스트에서 사라짐
- 스샷 3·5·7이 처리순서에서 도달 불가

**② 넷플릭스 해지 — 텍스트 6단계 vs 스샷 7장**
- 3번 "[멤버십 해지]를 누릅니다" → 열리는 건 스샷4 "아래로 스크롤". 정작 스샷5가 "멤버십 해지" 화면인데 도달 불가
- 스샷 3·5도 도달 불가

**③ 삼성 수리비 — 텍스트 5단계 vs 스샷 4장**
- 스샷 1·3·4가 전부 `linkedStep: 3`. 3번에서는 스샷1만 열리고 **스샷3(보증기간 탭)·스샷4(품목별 보증기간)는 도달 불가**
- 스샷3·4는 내용상 4번 단계에 속하는데 3번으로 잘못 묶임

> 참고: ②③은 클코 잘못이 아니라 **내가 넘긴 `넷플릭스_삼성_스샷가이드_2차.md` 스펙 자체에 linkedStep이 잘못 적혀 있었다.** 이번에 데이터·렌더러 양쪽을 같이 고친다.

## 1. 원칙 2개 (앞으로 계속 지킬 것)

> **원칙 1 — 업체를 안 물어봤으면 업체를 고르게 한다.**
> 링크 문구에 업체명이 없으면 그 링크는 절대 특정 업체 상세 페이지로 직행하지 않는다. 반드시 상황 허브(`/problem/...`)를 거친다.

> **원칙 2 — 스샷이 있는 페이지는 처리순서 번호 = 스샷 번호.**
> 스샷 n장이면 텍스트 단계도 그 n개 동작을 같은 순서·같은 번호로 담는다. `linkedStep: n`은 스샷 번호 n과 1:1. 확인·마무리처럼 스샷이 없는 단계는 맨 뒤에만 붙인다.

## 2. 작업 ① — 상황 허브 신설

### 2-1. 새 파일 `app/data/problems.ts`

```ts
import { companies } from "./services";

export type ProblemOption = {
  companySlug: string;
  serviceSlug: string;
  /** 목록에 곁들일 짧은 한 줄. 없으면 서비스 title만 표시. */
  note?: string;
};

export type Problem = {
  /** URL: /problem/<slug> */
  slug: string;
  /** 목록·링크에 쓰는 짧은 이름 */
  title: string;
  /** 페이지 h1 */
  heading: string;
  /** h1 아래 한 문단 */
  lead: string;
  icon: string;
  /** 업체 고르기 전에 공통으로 할 일 */
  firstAid: string[];
  /** 업체 선택 목록 위 안내 문구 */
  chooseLabel: string;
  /** 인기순으로 정렬해서 넣을 것 — 첫 번째가 강조된다 */
  options: ProblemOption[];
  /** "모르겠어요" 갈래 */
  fallback?: {
    label: string;
    note: string;
    links: { href: string; label: string }[];
  };
  faq?: { question: string; answer: string }[];
  /** 관련 허브 slug */
  related?: string[];
  lastChecked: string;
};
```

```ts
export function getProblem(slug: string) {
  return problems.find((problem) => problem.slug === slug);
}

/**
 * 빌드 때 한 번 돈다. 존재하지 않는 업체·업무를 가리키면 빌드를 깨뜨려서
 * 링크가 조용히 썩는 걸 막는다.
 */
(function assertProblemOptions() {
  const seen = new Set<string>();
  for (const problem of problems) {
    if (seen.has(problem.slug)) {
      throw new Error(`[problems] 중복 slug: ${problem.slug}`);
    }
    seen.add(problem.slug);

    if (problem.options.length < 2) {
      throw new Error(
        `[problems] ${problem.slug}: 고를 게 하나뿐이면 허브가 아니라 그냥 링크여야 합니다.`
      );
    }

    for (const option of problem.options) {
      const company = companies.find((c) => c.slug === option.companySlug);
      const service = company?.services.find((s) => s.slug === option.serviceSlug);
      if (!service) {
        throw new Error(
          `[problems] ${problem.slug}: 존재하지 않는 업무 ${option.companySlug}/${option.serviceSlug}`
        );
      }
    }
  }
})();
```

### 2-3. 새 페이지 `app/problem/[problemSlug]/page.tsx`

기존 상세 페이지(`app/company/[slug]/[serviceSlug]/page.tsx`)의 토큰·컴포넌트를 그대로 재사용한다. **새 디자인 시스템 만들지 말 것.** 스펙 v3 토큰(본문 17px, 굵기 700/600, 탭 48px, 읽기 폭 680px, 코랄은 화면당 1회)을 지킨다.

화면 순서(위→아래):

1. 브레드크럼 — `홈 / 상황별 / {title}`
2. `h1` = `heading`, 그 아래 `정보 확인일 {lastChecked}` 배지 (상세 페이지와 같은 컴포넌트)
3. `lead` 한 문단
4. **"업체를 고르기 전에"** 콜아웃 — `firstAid`를 체크 목록으로. 상세 페이지의 "지금 이것부터 하세요" 콜아웃 스타일 재사용
5. `h2` = `chooseLabel` → 업체 선택 목록
   - 각 행: `{업체명}` (굵게) + `{서비스 title}` + `›`, 탭 영역 최소 **56px**
   - **첫 번째 행에는 `많이 찾는 곳` 배지**(코랄 아님, primary-soft)를 달아 인기순임을 알린다
   - `note`가 있으면 업체명 아래 작은 글씨로
   - 모바일 1열, 데스크톱 2열
6. `fallback`이 있으면 목록 아래 회색 박스로 — `label`(굵게) + `note` + `links`
7. `faq`가 있으면 상세 페이지와 같은 아코디언 + **FAQPage JSON-LD**
8. `related`가 있으면 "이런 상황도 있어요" 링크 줄

구조화 데이터:
- `BreadcrumbList` (홈 → 상황별 → 현재)
- `ItemList` — `options`를 순서대로 (`position`, `name`, `url`)
- `FAQPage` — `faq` 있을 때만

메타:
```ts
title: `${problem.title} — 업체별 처리 방법`,
description: `${problem.lead} 업체를 고르면 처리 순서와 공식 링크가 바로 나옵니다.`,
alternates: { canonical: `/problem/${problem.slug}` },
```

`generateStaticParams`로 10개 전부 정적 생성.

```ts
  for (const entry of [...quickStarts, ...situationTasks]) {
    if (entry.kind !== "company") continue;
    const company = companies.find((c) => c.slug === entry.companySlug);
    if (!company) throw new Error(`[home] 없는 업체: ${entry.companySlug}`);
    const names = [company.name, ...company.aliases];
    if (!names.some((name) => entry.question.includes(name))) {
      throw new Error(
        `[home] "${entry.question}"에는 업체명이 없는데 ${company.name}로 직결됩니다. ` +
          `/problem/ 허브로 보내거나 문구에 업체명을 넣으세요.`
      );
    }
  }
})();
```

### 2-6. 검색 결과에도 허브 노출 (권장)

`app/search/page.tsx`에서, 검색 결과 목록 **맨 위**에 질의와 맞는 허브가 있으면 한 줄 띄운다.
매칭은 `problem.title` + `firstAid`가 아니라 **`problem.title`과 각 `option`의 업무 title·keywords**를 대상으로 기존 `similarity()`를 재사용해서 판단한다(별도 매칭 엔진 만들지 말 것).

표시 예: `카드를 잃어버렸어요 — 카드사 고르기 ›`

> **건드리지 말 것**: `app/search/page.tsx`의 자동 리다이렉트는 `mentionedCompanies.length === 1 && results.length === 1`로 이미 막혀 있다. 업체명이 없는 질의("카드 분실")는 리다이렉트되지 않고 목록을 보여준다 — **확인 완료, 정상이니 고치지 마라.**

### 2-7. 상세 페이지 → 허브 역방향 링크 (선택이지만 권장)

`app/company/[slug]/[serviceSlug]/page.tsx`의 `relatedSameTaskServices`(다른 업체 같은 업무) 블록 제목 옆에, 그 업무를 담고 있는 허브가 있으면 링크 한 줄을 추가한다. 예: 넷플릭스 `charged-after-cancel` 페이지 → "다른 곳에서 결제됐나요? → 해지했는데 또 결제됐어요". 내부 링크가 늘어나 허브 색인에 도움이 된다.
