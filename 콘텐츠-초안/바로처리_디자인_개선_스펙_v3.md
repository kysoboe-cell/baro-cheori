## 0. 한 줄 요약

지금 사이트는 **작은 글자(14px·12px) + 전부 굵기 900 + 연한 회색 + 박스 안의 박스** 조합이라 "예쁘게 꾸몄는데 읽기 힘든" 상태다. 잘 되는 사이트(토스·당근·카카오 고객센터·GOV.UK·NHS·Apple 지원)는 반대로 **본문 17~19px, 굵기 400/700 두 단계, 진한 회색 5단계, 박스 대신 여백**으로 읽힘을 만든다. v3는 그 규칙을 수치 그대로 가져온다.

### 3-3. 간격·모양·탭 영역

- 간격 스케일: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48. 섹션 간 **32px(모바일) / 48px(데스크톱)**, 제목 위 32 / 아래 16, 문단 간 16, 리스트 항목 간 8.
- 본문 폭: 상세 페이지 읽기 컬럼 **max-w 680px**, 좌우 padding 16px(모바일) / 24px. 메인 컨테이너 1280px 유지.
- 모서리: 카드 12px, 버튼 10px, 입력·칩 8px, 배지 full.
- 그림자: 사용 안 함(또는 `0 1px 2px rgba(0,0,0,.04)`). 구분은 `line` 1px 또는 배경 명도차로.
- 탭 영역: 모든 버튼·링크·썸네일 **min 48×48px**, 인접 간격 8px 이상. 주 CTA 높이 56px, 일반 버튼 48px.
- 포커스 링: `outline 3px solid #0f766e, offset 2px` (키보드 사용자).

## 4. 컴포넌트 규칙 (Before → After)

### 4-1. 헤더·카테고리
- 헤더 높이 56px. 로고 + 오른쪽 텍스트 링크 2개(각 48px 탭 영역). 데스크톱 "업체로 바로 찾기" 드롭다운 6개는 **칩 한 줄**(높이 40px, 15px/600, 선택 시 primary-soft 배경)로 교체 — 드롭다운 화살표 6개가 폼처럼 보이는 문제 제거.
- **모바일: 카테고리 2×3 그리드 삭제.** 순서를 헤드라인 → 검색창 → 카테고리 칩(가로 스크롤 한 줄, `overflow-x-auto snap-x`) → 카드로. 첫 화면에 헤드라인과 검색창이 반드시 보여야 함.

### 4-2. 히어로·검색
- 헤드라인 `display` 토큰(28/40, 700). 서브 문장 `body` #4e5968. "완전 무료입니다"는 문장 끝에 붙이지 말고 **별도 줄의 작은 배지**(primary-soft 배경, 15px/600 primary)로 — 지금처럼 한 단어만 코랄로 줄바꿈되는 고아 줄 방지.
- 검색창 높이 56px, 입력 17px, 버튼 "검색" 56px 코랄 유지(화면당 코랄 1회 원칙의 그 1회).
- 메타 줄("23개 업체 · 109개 실제 업무 · …") 14px ink-600.

### 4-3. 메인 카드
- "다들 이것부터 찾아요": **모바일 2열 격자**(카드 높이 ≈ 110px: 제목 17/600 두 줄 + 설명 14px 한 줄), 데스크톱 4열. 아이콘 사각형 48px 제거 → 20px 인라인 이모지/아이콘을 제목 앞에. 테두리 `line`, 그림자 없음, padding 16px.
- "내 상황과 같은 문장부터": 카드 대신 **리스트 행**(ListRow: 상하 16px, 왼쪽 태그 14px + 제목 17/600 + 오른쪽 chevron, 행 높이 ≥ 64px, 행 사이 `line-soft` 1px). 데스크톱 2열.
- 이유: 같은 내용을 카드보다 40% 적은 높이로, 더 큰 글자로 보여준다.

### 4-4. 상세 페이지 골격 (모바일 순서 = 읽는 순서)
1. 빵부스러기(14px) → **H1**(24/700) → 확인일 배지(14px, "정보 확인일 2026-08-20")
2. **"지금 이것부터 하세요" 1문장**: 박스 없이 `h3` 굵기 + 왼쪽 4px primary 바(inset) — 박스 안 박스 금지
3. 준비물: 칩 한 줄(✓ 결제한 쿠팡 계정 · ✓ 다음 결제 날짜)
4. **단계 리스트(StepList)** — 4-5 참조
5. 주의 콜아웃(최대 2개) — 4-6 참조
6. **스샷 격자** (있을 때만, 단계 리스트 직후 1회) — 5절 참조
7. 연락처·공식 링크 블록 → 모바일에선 하단 고정 CTA로도 노출 — 4-7 참조
8. FAQ(아코디언, 제목 17/600, 본문 17/1.65), 관련 업무 링크
- 데스크톱: 읽기 컬럼 680px + 오른쪽 사이드(준비물·주의·연락처) 유지. 사이드 카드도 테두리 1겹만.

### 4-5. 단계 리스트 (StepList) — 가장 중요한 컴포넌트
- 구조: `<ol>` 한 단계 = 한 행. 왼쪽 **번호 원 36px**(테두리 1px `line`, 숫자 17/700 ink-800), 원 사이 1px 세로 연결선. 오른쪽 본문 17px/1.65 ink-700, 행 상하 padding 16px, 왼쪽 들여쓰기 52px.
- **"꼭 확인" 단계**: 박스·밑줄·배경색 없이 → 번호 원을 코랄 채움(흰 숫자) + 문장 위에 라벨 `꼭 확인`(14px/600, accent 글자, accent-soft 배경, radius full) + 문장 700. 이것만으로 충분히 눈에 띈다.
- 문장 형식: `[마이쿠팡 > 와우 멤버십 > 해지하기]`처럼 **메뉴 경로는 대괄호 + `>`**, 눌러야 할 단어만 700. 화살표(→) 사용 안 함. 한 단계 = 한 행동, 한 문장 45자 이내.
- 단계가 7개를 넘으면 3~4개씩 묶어 소제목(h3)으로 나눈다. 접기/펼치기는 쓰지 않음(고령층이 놓침).
- 해당 단계에 스샷이 있으면 문장 끝에 텍스트 버튼 **"화면 보기"**(14px/600 primary, 탭 영역 44px) → 격자 라이트박스의 해당 장면을 연다.
- 삭제할 것: 단계 텍스트 밑줄 장식, 단계 카드 안의 민트색 박스, "총 5단계" 같은 12px 메타.

### 4-6. 콜아웃 3종 (페이지당 합계 2개 이하)
- 주의: 배경 warn-bg, 왼쪽 4px warn-line, 제목 "주의"(17/700 warn-text) + 본문 17px. 아이콘보다 제목 글자로 구분.
- 긴급(직접 전화·방문 필요): 상단 제목 바 danger 배경 + 흰 글자 17/700, 본문은 흰 배경.
- 참고: 왼쪽 8px `line` 바 + 본문 15px ink-600 (GOV.UK inset).
- "해야 할 것 / 하지 마세요"는 가로 2열 금지, 세로 스택. ✓ success / ✕ danger, "하지 마세요" 항목마다 "~하지 마세요"를 반복.

### 4-7. 하단 고정 CTA (모바일 전용, 상세 페이지)
- 높이 56px + `env(safe-area-inset-bottom)`, 좌우 16px, 버튼 2개: 왼쪽 **"전화 걸기"**(ink-900 배경·흰 글자, 번호 있을 때만) + 오른쪽 **"공식 페이지 열기 ↗"**(primary). 18/700.
- 스크롤 내리면 숨기고 올리면 다시 보임(TDS FixedBottomCTA 방식). 페이지 맨 아래 연락처 블록이 화면에 들어오면 숨김.
- **플로팅 "커피 후원" 버튼은 모바일에서 제거**, 데스크톱은 헤더 우측 작은 텍스트 pill로. (후원 기능 자체는 유지)

### 4-8. 링크·버튼
- 본문 링크: primary 색 + 밑줄(두께 1px, offset 0.16em), hover 두께 2px. 색만으로 링크 표시 금지.
- 외부 링크는 `↗` 표시 + `rel="noopener"`. 버튼 글자 17/600, 높이 48, 아이콘 단독 버튼 금지(라벨 동반).

## 5. 스샷 가이드 v2 — "한 화면에 흐름 전체"

유석 님 판정: 지금처럼 한 장씩 세로로 쌓으면 7장 = 5화면 → "한눈에"가 안 되고, 그럴 바엔 글만 두는 게 낫다. v2는 **격자 + 탭하면 크게**가 기본이다.

### 5-1. 데이터 (ServiceTask.screenshotGuide 확장)
```ts
screenshotGuide?: {
  checkedAt: string;        // "2026-08-20"
  basis: string;            // "넷플릭스 안드로이드 앱 화면 기준"
  steps: Array<{
    n: number;              // 단계 번호 (텍스트 단계 번호와 맞출 필요 없음)
    img: string;            // 전체 화면 720px WebP: /images/guides/<slug>/step1.webp
    thumb: string;          // 4:5 크롭 480×600 WebP: /images/guides/<slug>/step1-thumb.webp
    label: string;          // 격자 아래 짧은 라벨 2~6자: "나의 넷플릭스"
    caption: string;        // 라이트박스용 한 문장(45자 이내)
    alt: string;            // 화면 상태 서술
    linkedStep?: number;    // 텍스트 단계 리스트의 몇 번과 연결되는지("화면 보기" 버튼용)
  }>;
}
```
- `thumb`는 주석(동그라미·배지) 주변을 4:5로 잘라낸 파일. Cowork 쪽 가공 파이프라인이 step1.webp와 step1-thumb.webp를 항상 쌍으로 만든다(이번 넷플릭스 7장·삼성 4장에 이미 포함).

### 5-2. 레이아웃
- 섹션 제목: "화면 그대로 따라하기" (h2) + 오른쪽 확인일 배지 "2026년 08월 20일 · 넷플릭스 안드로이드 앱 기준"(14px).
- 격자: **모바일 3열**(`grid-cols-3 gap-2`, 390px에서 썸네일 ≈ 113×141px), 태블릿 4열, 데스크톱 **`grid-cols-[repeat(auto-fit,minmax(150px,1fr))]`**(7장이면 한 줄). 셀 = `thumb` 4:5 `object-cover` + 모서리 8px + 테두리 `line` + 좌상단 **번호 배지 24px(코랄, 흰 숫자 14/700)** + 아래 `label` 14px/600 ink-800 한 줄(말줄임). 셀 전체가 버튼(탭 영역 ≥ 48px).
- 7장 격자 전체 높이 목표: 모바일 **≤ 600px(한 화면)**. 라벨 포함.
- 라이트박스: `<dialog>`. 이미지 `img` 전체를 `max-h-[85vh] object-contain`, 아래 캡션 17px(번호 배지 + caption), 하단에 이전/다음 버튼 48px + "n / 7", 우상단 닫기 48px. 좌우 스와이프(touch) + 키보드 ←/→/Esc. `loading="lazy"`, `sizes`로 격자에선 thumb만 로드.
- 텍스트 단계의 "화면 보기" 버튼 → 같은 라이트박스를 해당 n으로 연다.
- 배치는 단계 리스트 **직후 1회**. 문단 사이에 흩뿌리지 않는다.

### 5-3. 캡처·가공 규칙 (콘텐츠 쪽)
- 페이지당 3~7장, **버튼이 숨어 있거나 함정이 있는 장면만**. 첫 화면(앱 홈) 같은 건 탭할 영역이 보이게 잘라서 쓰거나 생략.
- 가공: 상태바·시스템바 크롭, 개인정보 전부 가림(이름·이메일·전화·카드·날짜·금액), 코랄 #e85d3f 둥근 사각 주석 + 번호 배지, 전체 720px WebP ≤ 100KB + 썸네일 480×600 WebP.
- 신선도 표시 필수(`checkedAt`·`basis`). 공식 UI가 바뀌면 격자 전체를 내리고 텍스트만 남긴다.

### 5-4. 포기 기준 (유석 님 기준 명문화)
격자로 만들어도 모바일 한 화면에 흐름이 안 들어오거나(8장 초과), 썸네일에서 눌러야 할 버튼이 안 보이면(너무 작은 UI) → **그 페이지는 스샷 없이 텍스트 단계만** 둔다. 스샷은 텍스트를 대체하지 못하고 보조한다.

## 6. 작업 순서·검증 기준 (Claude Code용 체크리스트)

작업 순서: ① 토큰(tailwind.config·globals.css·Pretendard 스택) → ② 전역 치환(900→700, 12/13px→14px 이상, slate-400/500 텍스트→ink) → ③ 메인(헤더·칩·히어로·카드) → ④ 상세 페이지 골격·StepList·콜아웃·하단 CTA → ⑤ ScreenshotGuide v2(격자+라이트박스) + 넷플릭스·삼성 데이터 반영 → ⑥ 모바일 390px·데스크톱 1280px 검증 → 배포 → 푸시.

통과 기준(전부 수치):
- [ ] `font-weight: 900` / `font-black` 0건, 텍스트 12px·13px 0건 (푸터 법적 고지 13px 1곳만 예외 허용)
- [ ] 본문 17px 이상, 행간 1.6 이상, 텍스트에 slate/gray-400·500 0건
- [ ] 모바일 메인 첫 화면(390×844)에 헤드라인 + 검색창 + 카드 첫 줄이 보임
- [ ] 모바일 상세 페이지(쿠팡 와우 해지) 전체 높이 **8,586px → 4,500px 이하**
- [ ] 스샷 격자 7장이 모바일에서 **600px 이내**, 라이트박스 열기/닫기/좌우 이동 동작
- [ ] 단계 리스트에 중첩 박스 0개, 밑줄 장식 0개, "꼭 확인" 라벨 방식 적용
- [ ] 모든 버튼·링크 탭 영역 48px 이상(`min-h-12`), 하단 고정 CTA 56px + safe-area
- [ ] Lighthouse(모바일) Accessibility 95 이상, 콘솔 오류 0
- [ ] `npm run build` 142페이지 통과 → `npm run deploy` → 실사이트 200 → `git push` 후 `git log origin/main..main` 비어 있음

## 7. Claude Code 명령문 (복붙)

```
디자인 개선 스펙 v3를 적용해줘. 스펙 파일: 콘텐츠-초안/바로처리_디자인_개선_스펙_v3.md (이 파일을 먼저 끝까지 읽고 시작).

목표 한 줄: "글자 먼저, 박스 다이어트" — 시안 2 색과 카피는 유지하고, 글자 크기·굵기·회색 위계·여백·박스 구조·스샷 배치를 스펙 3~5절 수치 그대로 바꾼다.

작업 순서 (스펙 6절):
① 토큰: tailwind.config에 스펙 3-1 fontSize 토큰과 3-2 색 토큰(ink-900~500, line, line-soft, bg-soft, primary/-strong/-soft, accent/-soft, warn-*, danger, success) 추가. globals.css에 :lang(ko){word-break:keep-all;overflow-wrap:break-word}, body 17px/1.65 #4e5968, 포커스 링, 숫자 tnum 유틸.
② 전역 치환: font-black/900 → 700(display·h1·h2) 또는 600(h3) / text-xs·13px → text-caption(14px) / 텍스트의 slate-400·500·gray-400·500 → ink-600(ink-500은 플레이스홀더·아이콘만). 끝나면 grep으로 0건 확인해서 보고.
③ 메인: 헤더 56px + 텍스트 링크 48px 탭 영역. 데스크톱 드롭다운 6개 → 칩 한 줄. 모바일은 카테고리 2×3 그리드 삭제하고 순서를 헤드라인 → 검색창 → 칩 가로 스크롤 → 카드로. 히어로 헤드라인 display 토큰, "완전 무료입니다"는 별도 줄 배지. "다들 이것부터 찾아요"는 모바일 2열 격자(아이콘 사각형 제거), "내 상황과 같은 문장부터"는 ListRow 리스트(스펙 4-3).
④ 상세 페이지: 스펙 4-4 순서로 골격 재배치(읽기 컬럼 max-w 680px). StepList를 스펙 4-5대로 새로 만들기(번호 원 36px + 연결선, 꼭 확인 = 코랄 원 + 라벨, 밑줄·중첩 박스 제거, 메뉴 경로 [A > B] 표기, "화면 보기" 버튼). 콜아웃 3종(4-6). 모바일 하단 고정 CTA(4-7: 전화 걸기 + 공식 페이지 열기, 56px, 스크롤 내릴 때 숨김) 추가하고 플로팅 커피 버튼은 모바일에서 제거·데스크톱은 헤더 pill로.
⑤ ScreenshotGuide v2: 스펙 5-1 데이터 구조로 확장(thumb·label·caption·alt·linkedStep), 5-2 레이아웃(모바일 3열 격자 + <dialog> 라이트박스 + 이전/다음/닫기 48px + 스와이프·키보드) 구현. 기존 쿠팡 와우 해지 7장은 thumb가 없으니 임시로 img를 object-cover object-top 4:5로 보여주되, 넷플릭스(/company/netflix/membership-cancel)와 삼성 수리비(/company/samsung-electronics/repair-cost-warranty)는 콘텐츠-초안/넷플릭스_삼성_스샷가이드_2차.md의 데이터와 public/images/guides/ 아래 파일로 반영.
⑥ 검증: npm run build 142p → npx playwright로 390px·1280px 스크린샷(메인, 쿠팡 와우 해지, 넷플릭스 해지, 삼성 수리비) 찍어서 스펙 6절 체크리스트를 하나씩 수치로 확인(특히 상세 페이지 높이 4,500px 이하, 격자 600px 이내, 900/12px 0건) → npm run deploy → 실사이트 200·콘솔 오류 0 → 커밋·main 머지·git push(origin/main..main 비어 있는지 확인) → CLAUDE.md "0. 최신 상태 요약" 갱신.
```
