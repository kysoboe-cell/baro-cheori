## 1. 컬러 시스템 교체 — 시안 2 "틸 & 코랄"

현재 사이트는 blue 계열(blue-700, blue-50, #dbeafe, #60a5fa 등)이 헤드라인 강조·버튼·링크·배지·포커스링에 광범위하게 쓰임. 이걸 아래 팔레트로 전면 교체.

### 팔레트 정의

| 역할 | 값 | 용도 |
|---|---|---|
| Primary (틸) | `#0f766e` (= teal-700) | 핵심 CTA, 링크, 로고, 활성 상태, 강조 텍스트 |
| Primary 진한 톤 | `#115e59` (= teal-800) | hover/눌림 상태 |
| Primary 옅은 배경 | `#f0fdfa` (= teal-50) | 히어로 그라디언트, 카드 틴트 배경 |
| Primary 옅은 테두리 | `#99f6e4` (= teal-200) | 틴트 카드 테두리 |
| Accent (코랄) | `#e85d3f` | 포인트 전용 — 검색 버튼, "가장 먼저" 태그, 긴급 배지 등 **소수 요소만**. 남용 금지(화면당 1~2곳) |
| Accent 옅은 배경/테두리 | `#fff1ec` / `#ffd2c2` | 긴급 계열 카드 틴트 |
| 본문 텍스트 | slate-950 / slate-600 | 현행 유지 |
| ::selection | `#ccfbf1` (teal-100) | globals.css의 `#dbeafe` 교체 |
| :focus-visible 링 | `#14b8a6` (teal-500) | globals.css의 `#60a5fa` 교체 |

### 적용 방법 (권장)

Tailwind 4를 쓰고 있으니 `globals.css`의 `@theme`에 커스텀 토큰을 정의하고 클래스를 치환하는 방식 권장:

```css
@theme inline {
  --color-primary: #0f766e;
  --color-primary-dark: #115e59;
  --color-primary-soft: #f0fdfa;
  --color-primary-line: #99f6e4;
  --color-accent: #e85d3f;
  --color-accent-soft: #fff1ec;
  --color-accent-line: #ffd2c2;
}
```

이후 `bg-primary`, `text-primary`, `border-primary-line` 등으로 사용. 이렇게 해두면 다음에 색을 또 바꿀 때 토큰 값만 고치면 됨.

### 적용 범위 — 반드시 전수 치환

`blue`로 프로젝트 전체 검색(grep)해서 나오는 모든 파일: `app/page.tsx`, `app/components/CategoryFinder.tsx`, `HomeSearch.tsx`, `SiteHeader.tsx`, `SiteFooter.tsx`, `CoffeeSupport.tsx`, `PhoneActions.tsx`, 상세 페이지 템플릿(`app/company/...`), 검색 페이지 등 **메인+상세 전 페이지**. 하드코딩 hex(`#dbeafe`, `#60a5fa`, 히어로의 `linear-gradient(135deg,#f7f9ff,#eef5ff,#ffffff)` 등)도 잊지 말 것 — 그라디언트는 `linear-gradient(180deg,#f0fdfa,#ffffff)` 톤으로.

주의: 파랑을 기계적으로 전부 틸로 1:1 치환하지 말고, "강조가 과했던 곳"은 이번 기회에 slate 계열로 톤다운(기존 스펙의 색상 절제 원칙 유지). 핵심 액션에만 primary, 진짜 포인트 1~2곳에만 accent.

## 2. Pretendard 폰트 실제 로딩 (현재는 선언만 있고 로딩이 없음)

**현상**: `globals.css`에 font-family 1순위로 "Pretendard Variable"이 지정돼 있으나, 폰트 파일을 불러오는 코드(@font-face나 CDN link)가 어디에도 없음 → 방문자에게는 시스템 기본 글꼴(윈도우 맑은 고딕 등)로 보이는 중.

**수정**: `app/layout.tsx`의 `<html>` 안에 Pretendard Variable dynamic-subset CSS 로딩 추가 (한글 폰트라 dynamic subset이 용량 면에서 필수):

```html
<link rel="stylesheet" as="style" crossOrigin="anonymous"
  href="https://cdn.jsdelivr.net/gh/orioncactus/pretendard@v1.3.9/dist/web/variable/pretendardvariable-dynamic-subset.min.css" />
```

(Next.js에선 head에 직접 넣거나 preload 조합. 셀프호스팅을 선호하면 woff2를 `public/fonts/`에 두고 @font-face로 — 다만 dynamic subset의 용량 이점이 커서 CDN 방식 권장. Pretendard는 SIL OFL 라이선스라 상업 사용 무료.)

**로딩 후 확인**: 본문 크기 모바일 16px 이상 / 행간 1.6~1.7 유지, 히어로 헤드라인이 Pretendard 굵은 웨이트로 제대로 렌더되는지.

## 3. 메인 헤드라인·서브카피 교체 (문구 확정 — 수정 금지)

`app/page.tsx` 히어로:

- 헤드라인: **복잡한 ARS 싫으셨죠?**
- 서브카피: **처리 순서와 진짜 필요한 연락처까지, 검색 한 번이면 바로 나와요. 완전 무료입니다.**

연출 가이드:
- "완전 무료입니다"는 서브 안에서 강조(볼드 또는 accent 코랄) 가능
- 기존 배지 pill("전화 돌리기 전에, 지금 할 수 있는 것부터")은 **제거** — 히어로 세로 밀도 완화 목적
- 통계 줄(23개 업체 · 109개 실제 업무 · 공식 링크 표시)은 유지하되 더 작고 옅은 톤으로
- 메타데이터(title/description/OG)는 이번엔 건드리지 말 것 (SEO 안정화 중)

**절대 금지**: "버튼 위치까지 짚어주는", "화면 스샷으로 보여주는" 등 **아직 사이트에 없는 기능을 암시하는 문구**. (스샷 주석 콘텐츠가 실제 출시되면 그때 서브카피를 "버튼 위치까지 짚어주는" 버전으로 업그레이드 예정 — 지금은 아님.)

## 4. "지금 급한 문제인가요?" 카드 4개 주제 교체

방향: '진짜 급박한 문제' 위주 → **'수요 크고 은근 귀찮은 문제'** 위주로 (노출·체류시간 극대화, 유석 님 확정 방향). `app/page.tsx`의 `quickStarts` 교체:

| # | question | answer | 링크 |
|---|---|---|---|
| 1 | 쿠팡 와우, 그만 쓰고 싶어요 | 다음 결제 전 해지 순서 | `coupang/wow-membership-cancel` |
| 2 | 가전 수리비, 부르기 전에 궁금해요 | 출장비·무상보증 기준 먼저 | `samsung-electronics/repair-cost-warranty` |
| 3 | 해지했는데 또 결제됐어요 | 원인 확인과 환불 순서 | `netflix/charged-after-cancel` |
| 4 | 카드를 잃어버렸어요 | 분실신고부터 바로 | `kb-card/lost-card` (기존 유지) |

- 아이콘은 주제에 맞게 교체 (예: 🛒 / 🔧 / 💸 / 🔒)
- 섹션 제목 "지금 급한 문제인가요?"도 수요 프레임으로 교체 검토 — 제안: **"다들 이것부터 찾아요"** (배지 "많이 찾는 해결"과 톤 일치). 더 나은 안 있으면 자유, 단 과장·거짓 금지.
- 아래 `situationTasks` 6개는 유지하되, 위 4개와 주제가 겹치면(예: 디즈니+ 해지 후 결제) 다른 수요 큰 주제로 교체 가능 — 후보: 쿠팡 반품·환불, 유튜브 프리미엄 해지, 휴대폰 분실.

## 5. 모바일 우선 점검 (이번 개편의 기준 뷰포트 = 390px)

원칙: 1~4번의 모든 변경을 390px(아이폰 기준)에서 먼저 확인, 360px(갤럭시)도 한 번 확인, 데스크톱은 마지막. 아래는 현재 코드 기준으로 예상되는 모바일 개선 포인트:

1. **히어로 타이포**: 현재 모바일 `text-4xl`(36px)이 좁은 화면에서 과대 — 새 헤드라인("복잡한 ARS 싫으셨죠?")은 짧으니 모바일 `text-3xl`~`text-4xl` 사이에서 실제 스샷 보고 결정. `break-keep` 유지.
2. **카테고리 바**: 모바일 `grid-cols-3` 2줄 배치 유지하되 터치 타깃 최소 44px 확보(`py-2.5`가 아슬아슬 — 실측). 드롭다운 패널이 모바일에서 화면 폭에 꽉 차고(`left-4 right-4` 현행 OK), 업체가 많은 카테고리는 패널 내부 스크롤 가능하게 `max-h-[60vh] overflow-y-auto` 추가.
3. **터치 타깃 전수**: 모든 버튼·링크 min-height 44px (카드류는 이미 충분, 텍스트 링크류 확인).
4. **검색창 input**: 모바일에서 `font-size` 16px 이상인지 확인 (iOS에서 16px 미만이면 포커스 시 강제 줌 발생).
5. **상세 페이지 표**: 콘텐츠 보강으로 들어간/들어갈 표(수리비 참고표, 환불 소요기간 표)가 모바일에서 가로로 넘침 → `overflow-x-auto` 래퍼 필수 (또는 좁은 화면에서 카드형 변환).
6. **전화 액션**: 모바일에선 전화가 1순위 행동 — 상세 페이지의 `tel:` 버튼이 모바일에서 크고 명확하게(엄지 닿는 하단 근처면 더 좋음). PhoneActions 컴포넌트 확인.
7. **가로 스크롤 발생 여부**: 개편 후 홈·검색·상세 대표 페이지에서 body 가로 스크롤 없는지 확인 (`overflow-x` 새는 요소 탐지).
8. **커피 후원 버튼**: 모바일 우하단 고정이 콘텐츠(전화 버튼 등)를 가리지 않는지 확인.

**검증 페이지 세트** (Playwright 390×844 스크린샷): `/` , `/search?q=해지`, `/company/coupang/wow-membership-cancel`, `/company/samsung-electronics/repair-cost-warranty`, `/company/kb-card/lost-card`
