## 0. 수익화 우선순위 — 결정 (유석 님 위임에 따른 Claude 판단)

**공식: 수익 = 트래픽 × 페이지당 수익률.** 지금은 둘 다 사실상 0이다. 그래서 순서는 이렇게 간다.

**현실 수익 기대치부터 (과장 없이, 한국 후기 기반)**

| 월 페이지뷰 | 애드센스 대략 월수익 |
|---|---|
| 1만 PV | 약 1~4만 원 |
| 10만 PV | 약 10~40만 원 |

생활정보 주제의 RPM은 후기 기준 1,000뷰당 약 1,500원~2만 원으로 편차가 크고, 금융·보험보다 낮은 중간~하위 단가대다. **결론: 광고 설치는 "수도꼭지 달기"일 뿐이고, 물의 양(트래픽)이 수익을 정한다.** 그러니 광고 준비는 빨리 끝내되, 본게임은 계속 트래픽이다.

**우선순위**

1. **[오늘, 클코] 이 스펙 v6 반영** — 애드센스 사전 준비(1장) + 벤치마크 UX 개선(2장)을 한 번의 배포로. 돈 0원, 유석 님 시간 0분.
2. **[색인 첫 확인 시, 유석 님+기획실장 15분] 애드센스 신청.** 지금 바로 신청하지 않는 이유: 한국에 "개설 후 N개월" 공식 요건은 없지만(공식 문서 확인), **구글에 색인이 거의 안 된 상태에서 신청하면 "가치가 별로 없는 콘텐츠" 거절이 실제 후기에서 흔하고**, 거절 → 재신청 사이클이 2주+씩 잡아먹는다. 색인이 잡히기 시작하는 순간(예상 1~2주 내)이 승률과 속도를 둘 다 잡는 타이밍이다. 심사는 보통 3~14일. **색인 점검은 8/27 아침에 자동으로 돌아가도록 예약해 뒀다.**
3. **[이번 주부터, 반자동] 네이버 블로그 투트랙 시작 제안** — 색인 대기 중에 능동적으로 만들 수 있는 유일한 트래픽 레버. Claude가 Top 3 페이지(쿠팡 와우 해지·넷플릭스 해지·삼성 수리비) 요약 글 초안을 쓰고 본 사이트로 연결, 유석 님은 붙여넣기만. ※ 이건 제안 — "ㅇㅇ"라고 하면 다음에 초안부터 뽑는다.
4. **[예정대로] 9/3 색인 기준선 확인 → GA4 스샷 성과(2~4주) → Tier 3 결정.**

**모바일 최적화에 대해**: 유석 님 직감이 틀린 게 아니라 **이미 반영돼 있다.** v3부터 390px 기준 모바일 우선으로 갔고(본문 17px, 하단 고정 CTA, 스샷 격자, 2×3 그리드), v5에서 아코디언 모바일 확장까지 끝났다. 남은 건 "큰 공사"가 아니라 이 스펙의 잔손질이다.

## 1. 클코 작업 A — 애드센스 사전 준비 (승인 전에 해두는 것)

### 1-1. `/privacy` 개인정보처리방침에 광고·쿠키 섹션 추가

`app/privacy/page.tsx`에 아래 섹션을 추가한다 (문구 그대로):

> **광고와 쿠키**
> 바로처리는 서비스 운영을 위해 Google AdSense 광고 게재를 준비하고 있습니다. 광고가 게재되는 경우:
> - Google을 포함한 제3자 광고 사업자는 쿠키를 사용하여 이용자가 이 사이트 또는 다른 웹사이트를 방문한 기록을 바탕으로 광고를 표시할 수 있습니다.
> - 맞춤 광고는 Google 광고 설정(adssettings.google.com)에서 해제할 수 있습니다.
> - 자세한 내용은 Google 광고 정책(policies.google.com/technologies/ads)을 참고하세요.
>
> 바로처리는 이 외에 이용자를 식별할 수 있는 개인정보를 직접 수집하지 않으며, 방문 통계는 Google Analytics를 통해 익명으로 집계됩니다.

근거: 애드센스 필수 페이지 관행(후기 다수 공통) + 공식 문서는 "최신 정보 반영"만 요구.

### 1-2. 문의 수단 추가

`SiteFooter`에 한 줄: `문의: kysoboe@gmail.com` (mailto 링크). `/privacy` 하단에도 같은 문의처 표기. 승인 심사에서 연락처 존재가 관행상 권장 요건. ※ 나중에 전용 이메일로 바꾸면 이 두 곳만 수정.

### 1-3. 광고 슬롯 컴포넌트 — 지금은 잠든 상태로

새 파일 `app/components/AdSlot.tsx`:

```tsx
const ADS_ENABLED = process.env.NEXT_PUBLIC_ADS === "on";

/** 애드센스 승인 후 켜는 광고 자리. 꺼져 있으면 아무것도 렌더하지 않는다(빈 박스 금지).
 *  켜질 때는 CLS 방지를 위해 min-height를 CSS로 먼저 예약한다(공식 권장). */
export default function AdSlot({ id, minHeight = 280 }: { id: string; minHeight?: number }) {
  if (!ADS_ENABLED) return null;
  return (
    <div className="my-6" style={{ minHeight }} data-ad-slot={id}>
      {/* 승인 후 애드센스 in-article 코드 삽입 */}
    </div>
  );
}
```

배치 자리(지금 넣되 플래그 off라 화면 변화 0):
- 상세 페이지: ① 처리 순서 섹션 **끝난 뒤**(스샷 격자 앞) `id="in-article-1"` ② FAQ 섹션 **끝난 뒤** `id="in-article-2"`
- 허브(`/problem/`) 페이지: 업체 선택 목록 끝난 뒤 1개
- 데스크톱 사이드바: "직접 해결이 막혔을 때" 카드 아래 1개

**광고 금지 구역 (코드 주석으로도 박아둘 것)** — 조사에서 확인된 정책·관행 근거:
- "지금 이것부터 하세요" 콜아웃 내부, 처리 순서 **리스트 내부** (NerdWallet·Bankrate·Cleveland Clinic 전부 광고는 섹션 경계에만)
- **전화 걸기·공식 페이지 버튼 인접** — 오클릭 유도로 정책 위반 소지 (애드센스 공식 answer/1282097)
- **모바일 anchor 광고는 상세 페이지 금지** — 우리 FixedBottomCTA(하단 고정 전화/공식 버튼)와 겹쳐 오클릭 폭탄이 된다. anchor는 하단 CTA가 없는 홈·허브에서만 검토
- 홈 첫 화면 (토스·삼쩜삼 확인: 첫 화면은 액션만)

`app/layout.tsx`의 head에 `{/* AdSense 코드 삽입 지점 — 신청 시 pub ID 받으면 여기 */}` 주석 추가. ads.txt는 pub ID 없이는 의미 없으므로 지금 만들지 않는다(공식: 코드/메타태그/ads.txt 중 택1).

## 2. 클코 작업 B — 벤치마크 UX 개선 (확인된 패턴만)

### 2-1. 상세·허브 페이지에 점프 목차 한 줄

근거: WebMD(9섹션)·Bankrate(7섹션)·Healthline(18섹션) 모두 요약 직후 앵커 목차. 뱅크샐러드도 콘텐츠에 TOC. 우리 상세 페이지는 모바일 4,000px+라 효과가 크다.

- 위치: "지금 이것부터 하세요" 콜아웃 **바로 아래** 한 줄
- 형태: 텍스트 링크 행 (칩 아님, 밑줄 링크): `처리 순서 · 화면 따라하기 · 참고표 · 자주 묻는 질문 · 전화·공식 링크`
- 각 섹션에 id 부여: `#steps` `#screens` `#price-table` `#faq` `#official` — **그 페이지에 실제로 있는 섹션만 목차에 렌더** (스샷 없는 페이지에 "화면 따라하기" 링크 금지 — 거짓 0% 원칙)
- 탭 영역 48px 유지, `scroll-margin-top`으로 앵커 도착 위치가 헤더에 안 가리게

### 2-2. "도움이 됐나요?" 피드백 위젯 (GA4 이벤트)

근거: Bankrate 페이지 끝 "Did you find this page helpful?" 확인. 우리에겐 **스샷 가이드 성과 판정(2~4주 뒤 GA4 비교)에 쓸 직접 데이터**가 된다 — 체류시간보다 정직한 신호.

- 새 파일 `app/components/PageFeedback.tsx` (client). FAQ 섹션 뒤 배치: "이 안내가 도움이 됐나요?" + [도움됐어요] [아쉬워요] 버튼 2개(48px)
- 클릭 시 GA4로 전송: `gtag('event', 'page_feedback', { helpful: true|false, page_path: location.pathname })` — **layout에 gtag가 실제로 로드되는지 먼저 확인**하고, 없으면 GA4 measurement 스니펫 확인 후 진행. `typeof window.gtag === "function"` 가드 필수
- 클릭 후 그 자리에 "의견 감사합니다" 한 줄로 교체(레이아웃 밀림 0). 서버·저장소 없음, GA4가 저장소다
- 상세 페이지 + 허브 페이지에 배치

### 2-3. 홈 다크 밴드(01/02/03) 제거 → /about으로 이관

근거: 토스 고객센터·삼쩜삼 확인 — 잘되는 사이트는 과업 흐름 중간에 자기소개 선언문을 두지 않는다. 회사 이야기는 하단이나 별도 페이지.

- `app/page.tsx`의 `bg-slate-950` 섹션(01 공식 메뉴부터 / 02 현실적인 순서만 / 03 전화는 마지막에)을 삭제
- 그 3개 항목 텍스트는 `/about` 페이지에 "바로처리가 일하는 방식" 섹션으로 이관 (내용 버리지 말 것)
- 홈 맨 아래 "공식 정보를 바탕으로…" 흰 섹션은 유지 (신뢰 장치 + 정보 원칙 링크)

### 2-4. 확인일 표기 보강 + 면책 한 줄

근거: Bankrate·WebMD는 발행일·수정일 병기 + 갱신이력. 사람인·삼쩜삼은 결과 아래 면책 한 줄로 서비스 성격을 못박음.

- 상세 페이지 "정보 확인일 2026-08-20" 배지를 → "정보 확인일 2026-08-20 · 바로처리 직접 확인"으로
- 상세·허브 페이지 맨 아래(관련 링크 위)에 面책 한 줄: *"이 안내는 이해를 돕기 위한 정리이며, 실제 신청·처리는 연결된 공식 화면의 최신 조건 기준입니다."* — 텍스트 `text-caption text-ink-600`, 박스 치지 말 것

### 2-5. 검색 결과 페이지 v3 토큰 잔재 수정 (내가 코드에서 직접 발견)

`app/search/page.tsx`가 아직 옛 클래스(`bg-slate-50`, `text-slate-950`, `text-primary-700`, `text-sm` 등)를 쓰고 있다 — v3 개편에서 누락된 페이지. 검색은 모든 사용자가 지나는 길목이라 톤 불일치가 그대로 보인다.

- v3 토큰으로 통일: `bg-bg-soft` / `text-ink-900` / `text-primary` / `text-body-sm` 등 다른 페이지와 같은 매핑
- 굵기 900 금지·최소 14px·탭 48px 규칙도 이 페이지에 적용해 재점검

## 3. 안 하기로 한 것 (조사 근거 포함 — 다시 논의하기 전엔 하지 말 것)

- **다크모드** — 당근만 언급 확인, 한국 소비자 정보 사이트 표준 아님. 1인 운영엔 유지비만 늘어남
- **공유 버튼** — 뱅크샐러드·바로처리 포함 확인한 곳 모두 없음
- **가로 스크롤 큐레이션** — 토스피드급 대형 매거진 전용. 137페이지 규모엔 과잉
- **본문 중간 관련글 모듈 분산** — WebMD는 초장문이라 3곳 분산. 우리 페이지 길이엔 하단 1곳(현행)이 맞음
- **실시간 급상승·순위 배지** — 토스·뱅크샐러드 확인: 담백한 "많이 찾는" 라벨만 씀. 현행 유지
- **홈 첫 화면 광고** — 벤치마크 전멸 + 우리 원칙
- **wikiHow 방식 모방** — 접속 차단으로 실증 못 함. 확인 안 된 패턴은 채택 안 함 (거짓 0% 원칙의 조사 버전)
