## 1. 문제 — 11번가 링크가 2000년대 화석 페이지로 떨어짐

`/company/11st/cancel`, `/company/11st/return-refund` 등에서 [공식 페이지 열기]를 누르면 **"Mobile Station", QR코드, 이미지 메뉴가 나오는 옛날 페이지**가 뜬다 (유석 님 폰 실사용으로 발견, 스크린샷 확보).

원인: `app/data/companies/elevenst.ts`의 주문 관련 업무 **5개 전부**가 이 주소를 쓴다:

```
https://www.11st.co.kr/OrderDelvInfo.page   ← 화석. 데스크톱에서도 옛날 페이지가 뜸 (원격 실측 확인)
```

11번가가 옛 주소를 리다이렉트하지 않고 화석 페이지를 그대로 서빙하고 있다. **우리 코드 잘못이 아니라 링크 대상이 죽은 것** — 하지만 사용자 입장에선 우리 사이트가 이상한 데로 보낸 거다. "죽은 링크 강한 기피" 원칙 위반 상태.

## 2. 수정 — 검증된 현행 주소로 교체

**교체할 주소 (2026-08-21 원격 실측 완료):**

```
https://buy.11st.co.kr/my11st/order/OrderList.tam
```

검증 내용:
- 비로그인 접속 시 `login.11st.co.kr/auth/v2/login`으로 302 → **현행 최신 로그인 페이지**(카카오·네이버·패스키 지원, viewport 모바일 대응 확인) → 로그인하면 returnURL로 주문목록 복귀. 정상 동작 구조다
- 즉 "로그인 → 주문목록"으로 이어지는 11번가의 **현행 정식 경로**

### `app/data/companies/elevenst.ts` 수정 내용

아래 5개 업무의 `officialUrl`을 전부 교체하고, 링크 성격 표기를 맞춘다:

| slug | officialUrl (교체) | officialLinkType | lastChecked |
|---|---|---|---|
| `cancel` | `https://buy.11st.co.kr/my11st/order/OrderList.tam` | `"login"` | `"2026-08-21"` |
| `return-refund` | 〃 | `"login"` | `"2026-08-21"` |
| `order-check` | 〃 | `"login"` | `"2026-08-21"` |
| `delivery-not-received` | 〃 | `"login"` | `"2026-08-21"` |
| `return-pickup-delay` | 〃 | `"login"` | `"2026-08-21"` |

`officialNextStep`이 없는 업무에는 이 문구를 넣는다 (있으면 그대로):

```
로그인하면 주문 목록으로 이동합니다. 처리할 상품을 눌러 진행하세요.
```

**건드리지 말 것**: `customer-center`의 `https://cs.11st.co.kr/` — 원격 확인에선 내용이 비어 보였지만 이건 자바스크립트로 그려지는 최신형 페이지일 가능성이 높다(실브라우저에선 정상일 수 있음). 증거 없이 바꾸지 않는다. 다음 링크 전수 점검 때 실브라우저로 확인 예정.
