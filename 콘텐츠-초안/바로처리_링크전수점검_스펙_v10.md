## 1. 수정 ① — CJ대한통운 "배송완료인데 상품 없음" 링크가 B2B 사업소개로 변질됨

`app/data/companies/cjLogistics.ts` → `parcel-not-received`의 officialUrl:

```
https://www.cjlogistics.com/ko/support/guide/parcel
```

실브라우저 확인 결과 이 주소는 지금 **"국내배송 서비스 | 오네(O-NE) | 글로벌 SCM 솔루션 | 사업소개"** — CJ가 택배 브랜드를 오네(O-NE)로 개편하면서 소비자 안내 페이지가 **기업 영업 페이지로 바뀌었다.** 택배 안 왔다고 들어온 사람이 물류 영업 소개를 보게 되는 상황.

참고로 CJ 사이트의 `/ko/support` 계열은 전부 사업문의(B2B)로 재편됐고, `/ko/support/contact`는 404까지 확인했다. **소비자용으로 살아있는 건 `/ko/tool/parcel/` 계열뿐이다** (배송조회·반품예약 — 둘 다 정상 확인).

**수정**: `parcel-not-received`의 officialUrl을 아래로 교체. 이 업무의 액션 라벨("공식 배송조회 열기")과도 정확히 맞는다.

```
https://www.cjlogistics.com/ko/tool/parcel/tracking
```

`lastChecked: "2026-08-21"` 갱신.

## 2. 수정 ② — 신한카드 ARS 안내가 "가맹점(사장님)용" 페이지를 가리킴

`app/data/companies/shinhanCard.ts`에 있는 이 주소:

```
https://www.shinhancard.com/conts/store/customor_center/ars_gu/cardCounsel_voice.jsp
```

실브라우저 확인 결과 제목이 **"가맹점ARS이용안내"** — 카드 쓰는 고객이 아니라 **가맹점 사장님용** ARS 안내다 (경로에 /store/가 들어있는 게 그 뜻). 카드 분실하고 들어온 고객이 가맹점 결제 안내를 보게 된다.

**수정**: shinhanCard.ts에서 이 URL이 쓰인 곳을 찾아(고객센터 업무로 추정) 아래의 **고객용 상담 페이지**로 교체. 실브라우저로 확인 완료 — 제목 "상담하기 | 고객센터 | 신한카드", 고객센터 1544-7000·분실신고 1544-7200 등 고객용 번호가 정리된 페이지다.

```
https://www.shinhancard.com/pconts/html/bridge/2012734_40832.html
```

액션 라벨이 ARS 전제로 써 있으면 "신한카드 상담 안내 열기"로 맞추고, `lastChecked: "2026-08-21"` 갱신.

## 3. 확인 ③ — 로그인 리다이렉트 4곳, "로그인 필요" 표기 점검만

아래 링크들은 **깨진 게 아니라** 비로그인 시 정상적으로 로그인 페이지로 보낸다. 다만 사용자가 놀라지 않게 `officialLinkType: "login"`이 설정돼 있는지 확인하고, 없으면 넣어라 (문구 변경은 하지 말 것):

| 파일 | slug | 확인 결과 |
|---|---|---|
| lguplus.ts | `internet-trouble` (self-troubleshoot/request) | U+ID 로그인으로 이동 |
| lguplus.ts | `slow-internet`/`internet-trouble` 중 home-device 쓰는 쪽 | U+ID 로그인으로 이동 |
| netflix.ts | `membership-cancel` (cancelplan) | 넷플릭스 로그인으로 이동 (정상) |
| netflix.ts | `charged-after-cancel`/`payment-method` (account) | 넷플릭스 로그인으로 이동 (정상) |

삼성 reserveEngineer·reserveCenter도 로그인 리다이렉트인데 이건 기존에 알고 있던 사항 그대로다.
